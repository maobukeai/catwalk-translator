## 目标与边界

目标是让普通界面、聊天气泡、终端、密排工具栏、弹窗、图案混排、竖排与多栏内容都能可靠识别和原位显示。任何单套 OCR 对任意未知字体、遮挡、极小字、动画和图案都无法保证 100% 正确；产品需要在低可信度时明确呈现不确定性，并提供快速纠错入口。

### 2026-09-30 补充：静态原文加载反馈与原色保留

本轮保持默认原位模式、周边背景和 OCR 模型不变，仅修正两个可独立复现的显示问题。

- **灰色块不全是擦除失败**：真实终端第一行、端口检测行、绿色状态行的导出补丁逐像素检查均为正确的 `(12,12,12)` 黑底，浏览器里却有大块灰光。根因是卡片把 `translated === ''` 当作“正在翻译”，静态 OCR 原文也一直闪光并以 80% 不透明度显示。现在由实际翻译生命周期传入 `translationPending`；未启动、已完成、失败和“原文”视图均不再显示这层加载动画。真实翻译中的“原文↔译文”切换已有集成回归。
- **原色被强制黑白化**：真实终端绿色状态行的采样前景为 `rgb(21,180,12)`，旧亮度阈值却把它改成纯白。现在参照 [W3C 的 sRGB 对比度定义](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，前景与实际不透明擦除背景达到 4.5:1 时保留采样色；不足时选择对比度更高的黑或白。计算包含前景透明度，避免把几乎透明的白字误判为可读。背景本身、字号及字距不因此改变。

### 2026-09-30 补充：多栏与混合字号的原位排版

本轮仅调整原位覆盖的排版计算，不更改默认显示模式、周边背景模糊、OCR 模型或识别文本。

- **交错列顺序**：旧段落归组只记住全页最后一段，左右栏的 OCR 行交错时会丢失同栏连续关系。现在依据同左边界的最近前行归组；其它栏的控件不打断本栏，同栏插入的控件仍会阻断归组。
- **同高不等于同字号**：原来相同纵坐标的远处按钮会参与标题字号校正。现在只对相邻的短控件作同行校正；长标题、远端面板及多行块不参与。保留乱序工具栏、相邻节点传递关系的回归。
- **二次分组不稳定**：一组 18/23px 的 OCR 框高归一为 20.5px 后，原本有效的 31px 行距在第二次分组中会超限，导致统一字号失效。段落归属现固定依据原始框几何，不随估计字号变化。
- **长译文越栏**：浏览器样例实际复现 410px 左栏扩展成 672px 卡片、越过分栏线并把右栏挤下。仅当至少两个连续正文组在纵向相交、横向明确分离时，采用各段原文包围范围作为栏宽；短末行可使用本栏空间，用户放大后仍在栏内换行。单栏、分处上下的段落和工具栏继续走既有宽度路径。

研究上，OCR 识别器的自报置信度可能过高，不能单靠 0.99 判断正确；多引擎一致性与候选分歧可作为区域级复查信号，但必须按行/坐标对齐，并在本项目标注集上校准阈值。当前两次失败分别来自图标污染全图碎裂分数、局部坏行被整图聚合掩盖，支持优先做区域级路由与检测/识别/覆盖分环节评估，而非单纯更换默认模型。

擦除补丁检查又发现一个独立的显示缺陷：旧算法以整列中位色判断每行侧边样本，陡峭纵向渐变顶部的真实背景灰度 73 被误判为墨迹，补丁退回灰度 125，产生横向色带。现改为每行周围 25 行的局部中位色，仍过滤短小邻近墨迹。合成纵向渐变回归由失败转为通过；纯色、横向渐变、项目符号和用户密码标题原图的补丁测试也通过。此修复只针对规则/渐变背景：复杂纹理和图案上的整框横向插值仍可能失真。文献与 OpenCV 的传统修补接口都把文字掩码和背景重建分开；下一步应在真实失败截图上比较整框插值、笔画掩码加局部修补，并量化未翻译区域误盖与补丁色差，不能仅凭视觉观感切换算法。

后续审查原生 UI Automation 融合发现潜在的跨行误删：原代码只凭几何重叠就让控件 Name 替换 OCR，即使 Name 的矩形跨越多行。现仅在同一物理行且文字片段一致，或只有一个 OCR 框与 UIA 框高度、宽度接近时替换；宽大容器名称不再删除两行像素文字。TextPattern 已提供可见行时，不再重复加入该元素的辅助 Name；近方形按钮名称若按字高无法画进按钮，也不作为可见文字注入。对应合成单测覆盖跨行容器、单行纠错、同一行碎片合并及图标按钮。微软 UIA 规范允许可见范围不连续，矩形按可见行返回，因此必须保持这种逐行几何约束。此阶段尚缺真实应用中的 UIA/OCR 成对截屏标注，不能从合成单测推断所有应用都正确。

2. **量化四个环节**：检测框 precision/recall、文字字符错误率、行/列归属和原位覆盖的像素残留。把 OCR 文本正确与覆盖层视觉正确分开验收；记录每张图耗时、实际模型版本及回退原因。
3. **按区域选择识别器**：保留像素 OCR + WinRT + 原生 UI Automation；在碎片、低可信度或两引擎冲突的局部行做二次识别。只有候选在相同物理区域且覆盖更完整时才替换，避免用整张 WinRT 结果破坏终端和工具栏。
4. **适配复杂布局**：按文字行、按钮、图标、段落、表格/多栏区分区域。文本框合并需利用字高、行距、列间距与控件边界；文档类场景可选独立版面分析，不能把文档模型的阅读顺序直接套在桌面工具栏上。
5. **原位显示闭环**：对 OCR 框、擦除补丁与覆盖卡片用同一截图坐标系进行像素级比对；字号依据实际字形高度与可用宽度，并提供“显示原图/覆盖/并排”切换。低可信度文字先保持原图可读，并允许用户单框修改。
6. **模型升级须先 A/B 实测**：真实 v5 或 v6 Small 下载后在同一标注集比较准确率和速度，再决定默认选择；不能依据官方平均分直接切换用户默认模型。
